# 交接维护 · 可移植 Prompt(交给测评 / mlip-forge 等兄弟项目的 Claude Code)

> 把下面 `----` 之间的整段贴给对应项目仓库里的 Claude Code。它是本项目
> (EquiformerV3)交接实践的通用版:建立并**持续维护**一份 HANDOFF 主文档,
> 遵守测评同步纪律与 push 纪律,让项目随时可被接手、避免重复造轮子。

---

你负责维护本项目(测评 / mlip-forge / 其它)的**可交接性**。目标:接手者只读少数几份文档
就能还原当前进展、已做过的实验与当前最优,不必重造轮子。请遵守以下规则。

## 1. 建立并维护 HANDOFF 主文档
- 在 `docs/HANDOFF.md` 建一份**唯一入口文档**。仓库根目录只放 `README.md` / `CLAUDE.md`,
  其余所有 `.md` 一律进 `docs/`(或其子目录)。
- 建议章节:①目标+现状一句话(含当前最优数字)②环境/提交踩坑点 ③如何跑(管线/命令)
  ④可调配置空间(旋钮表)⑤历史大坑/被推翻的结论 ⑥已做消融速览(单变量结论+状态)+开放问题
  ⑦当前最优配方(ckpt 路径+完整配方+指标)⑧文件地图 ⑨协作/同步 ⑩维护规则。
- 顶部标"最后更新:<日期>"。**数字指向唯一真源,不在多处复制**。

## 2. 【自动要求·硬性】结果更新 → 更新 HANDOFF
**每当一次训练跑完、或一条测评结果到手,更新 HANDOFF 就是同一任务里的必做步骤,不是可选:**
- 新训练提交 → 在 HANDOFF「进行中/待回填」加一条;
- 测评数字回填(κ/F1/RMSD/CPS)→ 更新结果汇总表、把该 run 移出「待回填」、翻状态、
  若刷新则更新「当前最优」;
- 结论翻案 → 记进「历史大坑/修正区」;
- 每次都更新顶部"最后更新"日期。
**不允许把训练/测评结果只留在 chat / memory / 零散文档里。**

## 3. 测评结果同步纪律(若本项目会被测评)
所有 κ_SRME / F1 / RMSD / CPS 走双方共用的 **`EVAL_REGISTRY.md`**(git 跟踪,diff 即同步日志),
四条纪律:
1. 不可变键 = `ckpt_id`(提交时的 `--identifier`,也是 ckpt 目录后缀),**永不改名/删行**;
2. 一配方一行,换配方=新行,绝不覆盖旧行;
3. 列各有其主 —— 训练侧写 `status/ckpt_id/ckpt_path/stage/recipe/notes`,
   **测评侧只回填 `κ/F1/RMSD/CPS/eval_date` 并翻 `REQUESTED→DONE`,不做判断、不动配方列**;
4. 修正不动旧行(旧数字保留,重新解读写 notes 或"结论修正区")。
> 测评侧只按结果时间顺序回填;配方整理/解读**只在训练侧做**。

## 4. 每次 push 前的隐私排查
grep 排查:邮箱、API key / token、session URL、密钥、密码。
**这是团队私有仓库**(非公开开源)—— 内部集群路径、协作者名可以留;真·密钥/个人隐私不行。
命中敏感内容就**停下来问 owner**,不要擅自推送。

## 5. commit / push 纪律
- **未经 owner 明确同意,不 commit、不 push**;
- 若在默认分支(main),先开分支;
- commit message 用清晰描述;push 后回报 commit hash + 范围;
- 一次 commit 聚焦一类改动(文档 / 配方 / 代码分开)。
