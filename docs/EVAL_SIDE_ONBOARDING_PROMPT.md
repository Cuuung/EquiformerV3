# 给测评侧 Claude Code 的对接 Prompt

> 直接把下面 `----` 之间的内容整段贴给测评侧仓库里的 Claude Code 即可。
> 它假设两个仓库都能访问 `equiformer_v3/docs/EVAL_REGISTRY.md`(同一 git 仓库,或
> 约定好的共享路径)。若路径不同,把文中的路径替换成测评侧实际可达的路径。

---

你负责 EquiformerV3 模型的 Matbench Discovery 测评。我们和训练侧约定用**一个共用文件**做结果同步,消除"结果同步不及时、不清晰"的问题。这个文件是唯一真源:

**文件:** `docs/EVAL_REGISTRY.md`(训练侧仓库 `equiformer_v3/` 内,git 跟踪)

## 你的职责(只做这一件事:回填结果)

**你不做任何判断、不整理配方、不写解读。** 配方整理与结论解读全部由训练侧完成。
你只需要:**按结果产生的时间顺序,把测评数字填进对应行。**

## 规则(务必遵守)

1. **不可变键 = `ckpt_id`** 列(等于训练侧提交时的 `--identifier` 字符串,也是 checkpoint
   目录名的后缀)。你永远用这个键定位行。**绝不改名、绝不删行、绝不新建键。**

2. **你只写这几列**:`κ_SRME`、`F1`、`RMSD`、`CPS`、`eval_date`,并把该行 `status`
   从 `REQUESTED` 改成 `DONE`。
   - `κ_SRME / F1 / RMSD` 填原始测评值即可。
   - `CPS` 可留空(训练侧会用公式算);若你已有则填。
   - `eval_date` 填测评完成日期(YYYY-MM-DD)。

3. **你绝不修改** `ckpt_id / ckpt_path / stage / recipe / notes` 这些列(训练侧的列)。
   若某行 `ckpt_path`(时间戳目录)为空而你已知道,可**只补** `ckpt_path`,其余不动。

4. **只处理 `status = REQUESTED` 的行**。看到 REQUESTED 就去测,测完回填、翻 DONE。
   已是 DONE 的行不要动(哪怕你觉得数字应更新——重测结果由训练侧决定是否新增行)。

5. **找不到对应行怎么办**:如果你手里有一个测评结果,但表里没有匹配的 `ckpt_id`,
   **不要自己造行、不要猜键**。在文件末尾的"待训练侧登记"清单里追加一条:
   `- <你能识别该模型的信息:ckpt 路径 / 时间戳 / 你收到的名字> → κ=..., F1=..., RMSD=..., date=...`
   训练侧会补上正确的 `ckpt_id` 后再让你回填。

## 本次首要任务:补齐所有历史结果

请把**你手上目前所有的 EquiformerV3 测评结果**,按上面的规则填进 `docs/EVAL_REGISTRY.md`:

- 能用 `ckpt_id` 匹配到现有行的 → 直接回填该行,翻 DONE。
- 匹配不到的 → 按规则 5 追加到"待训练侧登记"清单(带上你能识别它的任何标识 + 数字 + 日期),
  **按结果产生的时间顺序排列**。

完成后请回一句话总结:填了几行、还有几条进了"待登记"清单。

---

## (文件里需要有的落脚点 —— 训练侧维护)

在 `docs/EVAL_REGISTRY.md` 末尾保留一个小节,供测评侧按规则 5 追加无法匹配键的结果:

```
## 待训练侧登记(测评侧填,键未知)
- <识别信息> → κ=..., F1=..., RMSD=..., date=...
```
