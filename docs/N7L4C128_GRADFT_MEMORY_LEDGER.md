# N7L4C128 (30M) 守恒力 grad-ft 显存台账

> 范围:30M EquiformerV3(N=7, Lmax=4, C=128)**守恒力 grad-ft 阶段**(fp32 + 双反向 `create_graph` + 应力,对 pos 和 displacement 双重求导)的显存/batch/atoms 全记录。
> 数据来源:(1) 集群真实 run 台账(`best_checkpoint.pt` 是否存在 = 是否跑过 step0);(2) 本地单卡 A100-80GB 实测(repo `.venv`,torch 2.7.1+cu126,plain 激活,`gradient_checkpointing_block_list=[1]×7`,真实 MPtrj 结构,完整 E→forces+stress 双反向,峰值 = `torch.cuda.max_memory_allocated`)。
> 关联:[`N7L4C128_CPS_REGRESSION_ANALYSIS.md`](./N7L4C128_CPS_REGRESSION_ANALYSIS.md)。

---

## 0. 一句话总纲

**显存由「每卡原子数(≈边数)」决定,不由 batch_size 数字本身决定。** `load_balancing:atoms` 把每卡原子数在 16 张卡间**压平**(而非设死上限)是真正兜底 OOM 的机制;`max_atoms` 砍单结构尾巴、`batch_size` 砍每卡均值,两个杠杆缺一不可。最终 **bs8 + max_atoms=150** 落在 ~80GB 墙下才跑通。

---

## 1. 集群 run 台账(16 GPU,全局 batch 512,fp32,守恒力+应力)

所有配置都保持全局 512(靠 grad_accum 补偿);区别只在**每卡 bs / accum** 和 **max_atoms**。

| 运行(日期后缀) | 每卡 bs × GPU × accum | max_atoms | 每卡均值原子数\* | 结果 |
|---|---|---|---|---|
| `06-21 …mlr1e-4` | ~bs16(×16×2)† | **24000(惰性)** | ~500 | **OOM @step0** |
| `06-23-03 …mlr5e-5` | ~bs16(×16×2)† | **24000(惰性)** | ~500 | **OOM @step0** |
| `06-23-04-01 …maxatoms150` | **bs16**×16×2 | 150 | ~500 | **OOM @step0**(仅剩 259 MB) |
| `06-23-04-09 …maxatoms150_bs8x16x4` | **bs8**×16×4 | 150 | ~250 | ✅ **跑通**(写出 best_ckpt) |

\* 均值 = 每卡 bs × MPtrj 全体均值 31.2 原子/结构。
† 这两条 OOM 早于 bs 后缀约定,run 目录未存 yml(step0 即死),bs 已不可精确复原;但 `max_atoms=24000` 惰性是主因,bs 是 16 还是 32 不影响定性。

**分水岭:** 惰性 24000 放行 150–444 原子尾巴 → 单个特大图就顶爆 → OOM;收到 150 但 **bs16 仍爆**(尾巴关了、均值批仍占满 80GB);**只有 bs8(每卡均值原子数减半)才真正跑通**。

---

## 2. 两种"原子数" —— 必须区分

**(A) 单个结构的原子数**(决定"最坏单图"):MPtrj 全体 142 万结构,均值 31.2,p50=22,p90=68,p99=**144**,p99.9=216,**max=444**。`max_atoms=150` 砍掉 0.82%(1.17 万个,即 150–444 尾巴),保留到 p99 之上。

**(B) 每卡一批里 bs 个结构的原子数总数/均值**(决定"每卡峰值显存"):

| 每卡 bs | 每卡均值原子数(=bs×31.2) | 每卡最坏抽样(balancing 后) |
|---|---|---|
| bs=32 | ~998 | 远超墙 |
| bs=16 | ~500 | ~压在墙上 → 爆 |
| bs=8 | ~250 | 有余量 → 稳 |

全局 512 结构 ÷ 16 卡由 `load_balancing:atoms` 把**每卡原子数**压平。

## 3. 实测显存曲线(单卡 A100-80GB;大结构打包 = 偏悲观上界)

| 场景 | 每卡原子数 | 峰值显存 | 结论 |
|---|---|---|---|
| 3 个大结构 | 298 | **55.1 GB** | OK |
| 3 个大结构 | 446 | **74.9 GB** | OK |
| **单个 444 原子结构(bs=1)** | **444** | **79.4 GB** | **OK,仅剩 ~0.6 GB** |
| 444 + 7 个单原子结构(bs=8,最优 balance) | 451 | **80.0 GB** | **刀尖上,实训必爆** |
| 8 个大结构子集 | ~600 | — | **OOM** |

拟合 ≈ **0.13 GB/原子 + 15 GB 基座**;**~450–480 原子/卡 ≈ 80 GB 墙**。

**对照实验(块级 checkpoint 与 `_mem` 激活):**

| 块级 ckpt | 激活 | 原子 | 峰值 |
|---|---|---|---|
| 开 `[1]×7` | plain | 298 | 55.1 GB |
| 开 | `_mem` | 298 | **55.1 GB(完全相同)** |
| 关 | plain | 298 | 64.9 GB |
| 开 | plain | 446 | 74.9 GB |
| 开 | `_mem` | 446 | **74.9 GB(完全相同)** |

→ **`_mem` 激活零收益**:`gradient_checkpointing_block_list=[1]×7` 已把整块(含 grid-MLP)在反向重算,`_mem` 的内层 checkpoint 冗余。块级 ckpt 本身省 ~10 GB(64.9→55.1)。且 `_mem` 的 grid-MLP checkpoint 用默认 `use_reentrant=True`,与守恒力 `autograd.grad` **不兼容**(关掉块级 ckpt 时直接崩)。**故 `_mem` 无法解锁 bs16,已弃。**

---

## 4. 把台账、原子数、显存曲线对上

- **bs8(~250 均值原子/卡,且多为小结构、边密度更低)** → 峰值远低于 55 GB → 稳。唯一跑通配置。
- **bs16(~500 均值原子/卡)** → 落在 446→75 GB / ~480→80 GB 墙区,balancing 后最坏抽样越墙 → 与实录"259 MB 差一点 OOM"完全对上。
- **惰性 24000 两条** → 444 原子尾巴入批,单个特大图就顶爆,与 bs 无关。

**对照:同一 30M 的 direct 阶段能 bs=32** —— direct 是 fp16(amp)+ 单反向 + 无应力,每样本显存约为 grad-ft 的 1/3–1/4。grad-ft 的 **fp32 + 双反向 + 应力**三重叠加,才是把可用 bs 从 32 压到 8 的根因(与卡数无关,纯每卡每样本显存)。

---

## 5. 每卡最大原子数 & 那个 444 原子结构能不能处理?

**每卡能跑的最大原子数 = 没有固定上限,而是 ~80 GB 的 OOM 墙。** `load_balancing:atoms` 不设死每卡原子数——它只在 16 卡间**均衡**(防止某张卡拿到所有大结构),每卡仍是**固定 batch_size 个结构**。峰值由"最坏一次全局批抽样(落进这 128 个结构里的大结构总量)÷16"决定,硬顶就是实测的 **~450–480 原子/卡 ≈ 79–80 GB**。

**444 原子最大结构:不是原则上跑不了,而是没法拼批。**
- **单独跑(bs=1):79.4 GB,能过** —— 但只剩 ~0.6 GB(`peak_reserved` 还更高,实训基本贴死)。
- **拼批即死**:哪怕和数据集里**最小的 7 个单原子结构**拼成 bs=8,也已到 **80.0 GB 刀尖**;真实 co-batch(均值 31 原子)必然越墙。
- 因为 `BalancedBatchSampler` 打**固定数量**(bs=8)、无法把巨型结构单独隔离成 bs=1 的微批,所以 444 在 bs≥2 体制下**无法容纳** → `max_atoms=150` 干脆丢掉它(丢 0.82%)。

**忠实的替代解(未实现):** 一个 **max-edges / 动态分桶采样器**,把巨型结构单独放进 bs=1 微批 —— 那样 444 就能以 79.4 GB 保留下来,不必丢。`max_atoms=150` 只是"直接丢"的廉价代理。这也是把每卡 bs 往上推的**唯一有效杠杆**(已确认 `_mem` 无效)。

---

## 6. 结论 / 可动杠杆

1. **生产配置 = bs8 × 16 × accum4 + max_atoms=150**(全局 512),已跑通,保留。
2. 要往 bs16 推,唯一有效杠杆是**进一步压每卡原子数**:真正的 max-edges 过滤 / 动态分桶采样器(需预算每结构边数写入 `metadata.npz`,并经私有 `metadata_path` 引入,不动共享数据集)。
3. **不要动的:** `_mem` 激活(实测零收益);块级 checkpoint 已是拉满的显存杠杆;fp32 强制(amp 会崩 Wigner 构造);`load_balancing:atoms`(真正兜底 OOM)。
